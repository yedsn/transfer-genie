# Spec Delta

## ADDED Requirements

### Requirement: 移动端消息窗口滑动返回
iOS 移动端 SHALL 允许用户在顶层消息详情及全屏新消息／草稿编辑器中，使用 UIKit 系统标准的左侧边缘向右滑返回原主窗口。手势 SHALL 由系统提供跟手、取消与完成反馈，并保留现有可访问的关闭操作。客户端 SHALL 复用同一个业务 WKWebView，不通过重载主文档实现顶层页面切换。

#### Scenario: 消息详情返回列表
- **WHEN** 用户在顶层消息详情从屏幕左侧边缘向右完成返回手势
- **THEN** 消息详情关闭并返回打开详情前的主窗口
- **AND** 原列表上下文及焦点按现有关闭行为恢复

#### Scenario: 立即打开原生导航页面
- **WHEN** 用户从主窗口打开消息详情或全屏编辑器
- **THEN** 目标页面在首帧直接呈现，不显示应用启动卡片或移动端初始化 loading
- **AND** 消息详情使用点击时的已加载消息立即显示内容
- **AND** 已初始化的控制器、当前草稿及原列表上下文继续复用，附件预览和同步在后台进行

#### Scenario: 取消原生返回手势
- **WHEN** 用户开始系统边缘返回后反向移动或取消手势
- **THEN** UIKit 使用系统交互动画恢复当前页面并保持打开
- **AND** 客户端不执行关闭事件、不销毁当前编辑器或重建草稿

#### Scenario: 无障碍和减少动态效果
- **WHEN** 用户使用关闭按钮、辅助技术或系统减少动态效果设置
- **THEN** 用户仍可通过关闭按钮返回
- **AND** 减少动态效果设置生效时避免不必要的位移动画

### Requirement: 滑动返回保护消息草稿
客户端 SHALL 仅在编辑器当前内容及附件、格式和标记设置已保存在原连接、账号和存储空间作用域时开放原生返回手势；不得由该手势发送消息。

#### Scenario: 保存草稿后返回
- **WHEN** 用户编辑文字或 Markdown、附件或标记设置后等待自动保存完成，再完成原生返回
- **THEN** 客户端确认当前快照已安全保存后允许系统关闭编辑器
- **AND** 重新进入原作用域的编辑器时可恢复已保存的内容
- **AND** 消息不会被发送

#### Scenario: 草稿无法保存
- **WHEN** 草稿未就绪、保存失败或当前编辑内容在保存期间发生改变
- **THEN** 客户端禁用原生返回手势，编辑器保持打开并保留当前内容
- **AND** 客户端给出可理解的状态或错误提示

#### Scenario: 附件选择或发送进行中
- **WHEN** 附件选择或消息发送尚未完成
- **THEN** 滑动返回不会关闭编辑器或中断进行中的操作

### Requirement: 滑动返回不干扰其他操作
客户端 SHALL 将返回手势识别交给 UIKit，并仅在顶层页面状态允许返回时启用，不得让手势穿透其他弹层或误触编辑及滚动操作。

#### Scenario: 非返回操作
- **WHEN** 用户纵向滚动、横向滚动内容或工具栏、编辑或选择文字，或进行多指操作
- **THEN** 客户端保留相应操作行为且不触发返回

#### Scenario: 非系统返回操作
- **WHEN** 用户从非左侧边缘开始横向操作，或执行系统未识别为返回的手势
- **THEN** 客户端不自行识别或播放返回动画

#### Scenario: 嵌套弹层打开
- **WHEN** 详情或编辑器之上打开标记设置、更多菜单、删除确认或其他弹层
- **THEN** 滑动不会穿透弹层关闭底层窗口
- **AND** 嵌套弹层的现有返回和确认流程保持不变
