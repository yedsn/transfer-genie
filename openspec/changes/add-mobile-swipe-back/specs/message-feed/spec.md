# Spec Delta

## ADDED Requirements

### Requirement: 移动端消息窗口滑动返回
移动端 SHALL 允许用户在顶层消息详情及全屏新消息／草稿编辑器中，从屏幕右侧边缘向左滑返回原主窗口。手势 SHALL 提供跟手与取消反馈，并保留现有可访问的关闭操作。

#### Scenario: 消息详情返回列表
- **WHEN** 用户在顶层消息详情从屏幕右侧边缘向左完成返回手势
- **THEN** 消息详情关闭并返回打开详情前的主窗口
- **AND** 原列表上下文及焦点按现有关闭行为恢复

#### Scenario: 不足阈值或取消手势
- **WHEN** 用户松手时滑动未达到返回阈值，或触摸被取消
- **THEN** 窗口恢复原位置并保持打开

#### Scenario: 无障碍和减少动态效果
- **WHEN** 用户使用关闭按钮、辅助技术或系统减少动态效果设置
- **THEN** 用户仍可通过关闭按钮返回
- **AND** 减少动态效果设置生效时避免不必要的位移动画

### Requirement: 滑动返回保护消息草稿
从编辑器滑动返回时，客户端 SHALL 在关闭前确认当前内容及附件、格式和标记设置已保存在原连接、账号和存储空间作用域；不得由该手势发送消息。

#### Scenario: 保存草稿后返回
- **WHEN** 用户编辑文字或 Markdown、附件或标记设置后完成滑动返回
- **THEN** 客户端先安全保存当前草稿，再关闭编辑器
- **AND** 重新进入原作用域的编辑器时可恢复已保存的内容
- **AND** 消息不会被发送

#### Scenario: 草稿无法保存
- **WHEN** 滑动返回时草稿未就绪、保存失败或当前编辑内容在保存期间发生改变
- **THEN** 编辑器保持打开并保留当前内容
- **AND** 客户端给出可理解的状态或错误提示

#### Scenario: 附件选择或发送进行中
- **WHEN** 附件选择或消息发送尚未完成
- **THEN** 滑动返回不会关闭编辑器或中断进行中的操作

### Requirement: 滑动返回不干扰其他操作
客户端 SHALL 仅在符合返回意图的单指手势时执行滑动返回，不得让手势穿透其他弹层或误触编辑及滚动操作。

#### Scenario: 非返回操作
- **WHEN** 用户纵向滚动、横向滚动内容或工具栏、编辑或选择文字，或进行多指操作
- **THEN** 客户端保留相应操作行为且不触发返回

#### Scenario: 反向或非边缘滑动
- **WHEN** 用户向右滑动或从非右侧边缘区域开始滑动
- **THEN** 客户端不将该动作识别为滑动返回

#### Scenario: 嵌套弹层打开
- **WHEN** 详情或编辑器之上打开标记设置、更多菜单、删除确认或其他弹层
- **THEN** 滑动不会穿透弹层关闭底层窗口
- **AND** 嵌套弹层的现有返回和确认流程保持不变
