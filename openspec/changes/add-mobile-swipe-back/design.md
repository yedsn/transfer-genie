# Design

## Context

移动端通过 `MobileShell.vue` 的 `activeSheet` 管理详情、编辑器和嵌套弹层。`closeSheet()` 已处理标记、更多菜单及删除确认的层级；`dismissSheets()` 对编辑器保存采用异步发起后立即关闭，不能直接作为新增手势的保存成功保证。草稿持久化接口返回成功状态，并携带连接、账号和空间作用域及变更版本校验。

## Goals / Non-Goals

**Goals:**

- 使用 iOS 原生左缘返回，并保持滚动、选区和辅助功能可用。
- 通过异步保存确认与窗口身份检查，避免因关闭、并发编辑或作用域变化丢失草稿。

**Non-Goals:**

- 不新增已发送消息正文编辑，不改变其他弹窗的返回语义、桌面端或服务端协议。
- 不承诺修改所有现有关闭入口的保存语义；本变更必须保证新增滑动入口安全。

## Decisions

### 原生导航替代方案（Simulator 原型通过，业务接入待确认）

2026-10-30 独立 Simulator 对照已证明：标准 UIKit push/pop 可以通过真实 XCTest 左缘拖动完成返回，而无业务插件的 WKWebView 在真实链接、本地 HTML、滚动已开启、移除诊断监听等条件下仍不完成历史返回。下文真实文档 History 方案保留为失败路径记录，不得据此宣称业务手势已经可用。

建议改用公开的 UINavigationController / interactivePopGestureRecognizer，复用同一个业务 WKWebView。主窗口由原生快照保留为返回转场背景；打开详情／编辑器时将同一个 WebView 移到原生子控制器，Vue 在同一文档里打开目标页，不重跑控制器初始化、不重新恢复草稿、不新建第二个 WebView。系统负责 push、跟手、速度、取消和 pop；取消时不修改 Vue 页面或销毁编辑器。完成 pop 后把 WebView 放回主控制器，再关闭 Vue 顶层页和移除原生快照。主列表上下文和已保存草稿仍保留在原控制器内存中。

独立原型验证范围：隐藏导航栏的公开 UIKit 返回、原生允许／禁止返回、短滑取消后再次返回，以及重新打开时保留相同编辑内容。关键系统手势优先级为 WebView 根滚动 pan.require(toFail: interactivePopGestureRecognizer)，否则编辑器获得焦点后滚动手势可能抢占返回。不得修改系统私有手势实现、调用模拟 swipe API 或用前端位移替代。此原型证据不等价于正式 Tauri shell、嵌套滚动、原生 picker 或冷启动草稿验收。

接入需要原生准备／显示／关闭命令和返回完成事件：准备时捕获主窗口快照，Vue 打开目标页并完成 nextTick 后再显示原生子控制器；显式关闭同样复用原生 pop。JS 内容变动和嵌套状态改变时同步撤销保存安全状态，并请求关闭原生返回 gate。系统 delegate 只在顶层子控制器、安全 gate 以及没有活动转场时允许开始；系统完成事件不能发送消息，只执行现有关闭、焦点和页面上下文恢复。返回取消不发关闭事件。桥接有延迟，接入时必须独立验证安全 gate，不能沿用旧设计的 popstate 校验作为保证。

这是导航架构调整，正式业务实现前需确认替代方案。无服务端或数据库迁移，原生和前端既有账号、草稿、同步逻辑继续复用。

### 旧方案：WKWebView 原生历史（未通过，待替换）

顶层 `detail` 或 `composer` 通过带内部页面参数的应用入口执行一次真实主文档导航，Swift 插件为承载应用的 `WKWebView` 启用 `allowsBackForwardNavigationGestures`。消息详情快照短暂保存在同一 WebView 会话的 `sessionStorage`，编辑器从本机持久化草稿恢复；iOS 因而使用系统标准的左侧边缘向右滑，原生负责手势竞争、页面快照、跟手、取消、速度和完成动画。显式关闭按钮复用 `history.back()`。

内部页面参数必须在入口 HTML 首次绘制前同步识别并隐藏全局启动卡片；Vue 首次渲染直接打开对应详情或编辑器，不等待控制器完成 SQLite、Keychain 与 Supabase 初始化。详情首帧使用会话快照；编辑器先保持最终布局并禁用输入，在后台恢复持久化草稿后原位变为可编辑。Markdown 编辑器代码在主列表空闲时预取，避免恢复 Markdown 草稿时额外等待。内部导航不得显示全屏 spinner 或初始化文案。

内部页面的弹层容器不额外淡入，避免页面导航后叠加第二段显现动画。草稿恢复前同时禁用格式切换；初始化失败时在当前页显示简短错误，保留已有详情内容而不切回全屏初始化界面。空闲预取失败不影响正常导航，离开主列表时取消尚未触发的预取回调。

不能使用 `pushState` 或 hash 代替真实导航：iOS WKWebView 不会将这两类 SPA 同文档记录加入 `WKBackForwardList`，即使 `history.length` 在普通浏览器中增加，也不会令 `canGoBack` 生效或启动系统交互式返回。

前端不再监听触摸事件或计算位移、距离和速度，也不提供自制全屏滑动动画。只有顶层详情或安全的顶层编辑器可以启用原生返回；横向工具栏、文字选择和嵌套弹层打开时禁用。返回主窗口后禁用原生手势，避免进入与应用状态不一致的浏览器历史。

旧评估认为 `UINavigationController` 需要拆成多个 WebView；单 WebView 原型已证明无需如此。前端模拟滑动仍不符合用户要求，不能作为替代方案。

### 层级与保存

候选 UIKit 接入中，原生子控制器与 Vue 顶层页面身份一一对应；任何其他弹层位于顶层时关闭原生手势，不绕过已有确认。完成返回时恢复同一主窗口的列表上下文。转场快照只是临时视图，不能替代草稿保存或成为数据来源。

编辑器只有在当前完整快照已经持久化、草稿已就绪、输入法未组合输入，且附件选择和发送均未进行时才启用原生返回。任何输入、格式、附件或标记变化都同步撤销“已持久化”状态并立即关闭原生返回；串行自动保存成功且窗口、作用域和完整快照仍一致后才重新开启。保存失败时保持编辑器并提示原因。

现有 `composerMutationVersion` 用于持久化失效等状态变更，并非每次编辑递增，不能单靠它证明写入期间草稿未改变：实现时需增加可靠的内容版本跟踪，或对完成前的完整草稿快照及作用域进行比较。原生保存空草稿会删除对应记录并返回空的更新时间；这属于成功清理，不能以时间戳为空误判为失败。预览模式的保存仅更新内存时间戳，不能用于证明原生持久化和冷启动恢复。

键盘显示时仍需让草稿保存错误可见且可由辅助技术感知。原生返回未开放时，关闭按钮继续提供可理解的保存中或失败反馈。

备选方案：直接调用现有 `dismissSheets()` 的 fire-and-forget 保存无法在失败时保留编辑器；弹出丢弃确认则偏离现有草稿自动保存习惯。

## Risks / Trade-offs

- [UIKit 调整 WebView 所属视图] → 保留同一业务 WKWebView 和原控制器，正确使用 UIKit containment；正式接入验证 Tauri 桥接、重复打开、横竖屏、键盘、picker、后台与取消后的状态恢复。
- [保存状态经 JS/Swift 桥接存在短暂延迟] → 内容变化时同步标记未持久化并立即请求禁用；接入需用并发和故障注入证明安全 gate。当前没有 `popstate` 返回校验，不将它写作已有保证。
- [浏览器预览模拟保存与原生持久化不同] → 原生 Simulator 使用隔离测试数据验证保存、恢复和错误提示；避免覆盖用户真实草稿。
- [系统左缘手势较难发现] → 现有关闭入口继续可用，并遵循用户已熟悉的 iOS 系统行为。

## Migration Plan

候选替代方案涉及 Swift 原生导航和 Vue 页面状态，不是纯 CSS 修改；无数据迁移。用户确认后先接入并完成正式 Simulator 自动化，随后在用户设备上验收。回滚保留既有关闭入口和草稿持久化逻辑，不卸载 App、不清理账号或数据库。
