# Design

## Context

移动端通过 `MobileShell.vue` 的 `activeSheet` 管理详情、编辑器和嵌套弹层。`closeSheet()` 已处理标记、更多菜单及删除确认的层级；`dismissSheets()` 对编辑器保存采用异步发起后立即关闭，不能直接作为新增手势的保存成功保证。草稿持久化接口返回成功状态，并携带连接、账号和空间作用域及变更版本校验。

## Goals / Non-Goals

**Goals:**

- 在触屏下安全地识别用户指定的从右向左返回，并保持滚动、选区和辅助功能可用。
- 通过异步保存确认与窗口身份检查，避免因关闭、并发编辑或作用域变化丢失草稿。

**Non-Goals:**

- 不新增已发送消息正文编辑，不改变其他弹窗的返回语义、桌面端或服务端协议。
- 不承诺修改所有现有关闭入口的保存语义；本变更必须保证新增滑动入口安全。

## Decisions

### 手势识别与视觉反馈

只在顶层 `detail` 或 `composer` 生效；在屏幕右侧约 24–32 CSS 像素区域开始识别，具体宽度与距离／速度阈值在 Simulator 调优。仅跟踪单指：经过方向锁定且水平位移显著大于垂直位移后，识别从右向左的拖动；未达阈值、反方向、第二指加入、触摸取消或窗口变化均恢复原位。达到完成阈值后先完成安全检查再退出，回弹及退出动画尊重 `prefers-reduced-motion`。

仅捕获明确的返回手势，优先保留可横向滚动区域、编辑器插入点和选区等原有操作；不全局禁用滚动或文字交互。必须在 WKWebView 中验证触摸事件、键盘和系统边缘手势的竞争；若边缘区影响编辑或无法稳定识别，需调整可触发区域并重新评审，不得以吞掉普通操作为代价。保留显式关闭按钮。

备选方案：全屏任意位置左滑容易与内容、Markdown 工具栏和文本操作冲突；iOS 常见的左边缘向右滑虽然更符合系统惯例，但不符合本次指定方向。

### 层级与保存

手势开始和完成时都校验当前顶层窗口及其身份；任何其他弹层位于顶层时不处理底层手势，不绕过已有确认。详情返回复用现有关闭和焦点恢复行为。

编辑器在附件选择、发送或草稿未就绪时不执行返回。完成手势后保持编辑器可见，冻结或阻止新的编辑直至强制保存结果返回；保存成功且窗口、作用域和内容版本仍一致时才关闭，否则恢复交互并提示原因。保存使用现有串行持久化和草稿作用域，不把尚未完成的保存视为成功；需要处理输入法组合输入和 Markdown 最后一次更新，确保快照包含最终输入。避免重复写入或异步回调在页面更换后关闭新窗口。

现有 `composerMutationVersion` 用于持久化失效等状态变更，并非每次编辑递增，不能单靠它证明写入期间草稿未改变：实现时需增加可靠的内容版本跟踪，或对完成前的完整草稿快照及作用域进行比较。原生保存空草稿会删除对应记录并返回空的更新时间；这属于成功清理，不能以时间戳为空误判为失败。预览模式的保存仅更新内存时间戳，不能用于证明原生持久化和冷启动恢复。

键盘显示时 `.mobile-compose-actions` 被隐藏，其中包含现有草稿错误信息；滑动保存失败或未就绪时，提示必须在键盘打开状态下仍可见并可由辅助技术感知，不能只复用隐藏区域。

备选方案：直接调用现有 `dismissSheets()` 的 fire-and-forget 保存无法在失败时保留编辑器；弹出丢弃确认则偏离现有草稿自动保存习惯。

## Risks / Trade-offs

- [右边缘区域可能与系统手势、选区、横向滚动冲突] → 保守的方向锁定和区域排除，覆盖实际 WKWebView 测试；明确保留关闭按钮。
- [保存期间状态被修改或窗口切换] → 编辑阶段短暂锁定、检查身份／版本／作用域，失败保留窗口，不发送消息。
- [浏览器预览模拟保存与原生持久化不同] → 原生 Simulator 使用隔离测试数据验证保存、恢复和错误提示；避免覆盖用户真实草稿。
- [仅右边缘启动较难发现] → 现有关闭入口继续可用；手势区域宽度由 Simulator 和后续真机可用性验证调整。

## Migration Plan

仅前端交互变更，无数据迁移。先做自动化和 Simulator 测试，确认后在用户设备上验收；回滚时移除手势入口，保留既有关闭及草稿持久化逻辑。
