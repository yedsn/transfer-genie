# Proposal

## Why

移动端消息详情和全屏消息编辑器目前主要依靠关闭按钮返回，单手操作不够方便。增加明确且可取消的滑动手势，可以让用户更自然地返回消息列表，同时避免误触造成草稿丢失。

## What Changes

- 在 iOS 移动端顶层消息详情和现有全屏新消息／草稿编辑器中，通过 UIKit 原生导航控制器复用同一个 WKWebView，使用系统标准的左侧边缘向右滑返回主窗口，并由系统提供推入、跟手、取消和完成动画。
- 顶层页面在同一文档内切换，避免每次打开重跑初始化；原生快照只用于转场，不代替业务数据或草稿持久化。
- 编辑器返回前确认当前草稿已安全保存；保存失败或附件选择、发送正在进行时不得通过该手势关闭编辑器。
- 删除前端自制滑动识别和位移动画；通过原生手势开关避免与未保存草稿、附件选择、发送和嵌套弹层冲突，并保留现有关闭按钮及无障碍操作。
- 本次不新增已发送消息正文编辑功能，也不改变其他弹窗或桌面端交互。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `message-feed`: 增加移动端消息详情及消息草稿编辑器的滑动返回与草稿保护要求。

## Impact

- 影响移动端 Vue 页面状态、Swift 原生控制器与 WKWebView 视图归属、消息草稿保存状态和相应测试。
- 不引入服务端协议、数据库结构或桌面端行为变更；需在 iOS Simulator 验证，随后进行真机验收。

## Approval Status

2026-10-30 用户已确认采用右侧推入、原生侧滑返回的 UIKit 单 WebView 方案。独立 Simulator 原型已通过 3 项 UIKit 导航测试；原型结果不算业务完成，正式接入仍需完成草稿、嵌套弹层、Simulator 和真机验收。
