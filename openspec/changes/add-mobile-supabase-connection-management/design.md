# Design

## Context

动机见 `proposal.md`。现有 `StorageProfile` 已包含稳定 ID、名称、启用状态、Provider 和 Supabase 地址/公开 Key/Space；后端会话按 profile 保存，系统凭据库负责长期会话。无需新增 `connections[]`。一张管理卡片对应一个 profile，即已保存的服务连接、账号及选定 Space；同一服务的不同 Space 可以有不同 profile。

移动端 `mobile-controller.ts` 初始化只保留已启用 Supabase profile，导致禁用配置不可管理；`MobileShell.vue` 的 `spaces` 弹层枚举当前账号下的远端 Space，而不是连接。已有 `chooseProfile` 会保存草稿，但通过旧的整份 settings 提交活动 ID；新增配置流程会把临时登录结果写进活动账号状态，不能直接用于新增第二个连接。

现有后端已提供绑定流程、profile 增改/移除和原位 Space 切换。`switch_supabase_space_impl` 会在保护检查后重建旧镜像和游标，因此不能用于 profile A → B 切换。`remove_storage_profile_impl` 默认阻止移除当前连接或有待处理工作的连接，强制操作可能放弃工作；移动端不得照搬 PC 当前默认强制移除的调用方式。

关联变更 `defer-supabase-space-creation` 仍未完成。其显式创建、统一绑定状态、旧配置迁移等设计不能当作当前代码事实；本设计依赖其绑定契约，而不重新定义这些机制。

## Goals / Non-Goals

**Goals:**

- 将「所有已保存配置」「可选择连接」「当前账号的远端 Space」「新增/编辑草稿」分成明确状态边界。
- 用共用后端转换保证设置新鲜度、连接归属和失败一致性；前端禁用按钮不作为唯一保护。
- 快速选择不依赖在线列出 Space，保留离线切换和本地优先体验。
- 通过可重放的异步隔离与失败测试验证草稿、队列、凭据和媒体不串连接。

**Non-Goals:**

- 不另建账号系统、profile 持久化模型或同步引擎；不对 PC 管理页做视觉改版。
- 不把连接卡片等同于 Supabase 项目列表；一个 profile 仍只绑定一个选定 Space。
- 不新增全连接后台同步、跨连接导入、WebDAV 或签名/分发方案。
- 不包办关联变更的完整 SQL、Space 创建协议及旧配置分类迁移。

## Decisions

### 1. 复用 profile，分离配置列表与远端空间列表

管理数据由最新 settings 的全部 Supabase profile 生成，包括禁用项；快捷选择从中筛选可激活项，显示其他项的不可选原因或管理入口。远端 Space 只属于指定连接或指定临时绑定流程，进入重绑/修复页后按需加载，不作为启动和打开管理页的阻塞条件。

卡片展示名称、可折行的服务地址、当前标识、账号摘要、绑定空间摘要和小型状态文字；状态未知、检查中、网络失败、需登录、绑定异常、禁用分开表达。由绑定契约核验有效性，不只依据前端是否有一个非空 `space_id`；离线时保留已知绑定及缓存，未知网络状态不等于绑定已失效。

备选是新增独立连接实体或把远端 Space 自动生成为卡片，均会形成新的标识、凭据映射和迁移成本，也偏离现有 profile 的隔离单位，故不采用。

### 2. 管理页全屏，快捷选择与远端重绑分开

「我的 → 存储空间」进入全屏卡片管理页；每个连接独立卡片，以当前标识和简短状态区分，主操作为选择/管理，编辑、启停、退出和移除进入该卡片的操作菜单。首页保留紧凑名称与同步文字，点击打开轻量连接选择 sheet，底部提供完整管理入口。

连接内的「更换远端空间」在设置/修复上下文中单独操作，不与首页快捷选择共享语义。无配置、未登录、绑定异常或错误页提供相同的管理/新增/其他连接入口，不让用户困在失败的启动流程里。

复用已有移动全屏层、安全区域和焦点/inert 处理，不照搬桌面表单布局。按钮至少 44pt；长地址折行或截断带完整查看能力，Key 默认遮蔽，键盘下步骤和操作可滚动到达，大字号不依赖固定卡片高度。

备选是继续扩展现有 Space 弹层，内容容易混淆连接与空间，并难承载四步配置、错误恢复和大字号，故只保留它作为明确的 Space 选择子流程。

### 3. 独立且可取消的四步向导

建立独立的新增草稿状态，包含步骤、名称、地址、公开 Key、测试结果、临时 flow ID、脱敏账号摘要、Space 候选/选择和请求代次；不能复用活动 `state.account`、`state.spaces` 或通过 `boot = needs-space` 替换当前应用上下文。首次配置复用同一向导，但退出后回到可新增的空状态。

使用现有草稿连接测试、临时登录、列出 Space、完成绑定和取消接口，refresh/access token 继续由 Rust 管理。修改地址/Key 清除下游登录和选择并取消旧 flow；切换账号使 Space 结果失效；关闭向导取消 flow 并清理密码。晚到结果按 flow ID、参数指纹和请求代次拒收。取消失败时界面不能重新接收旧 flow，后端依靠短生命周期到期清理，不持久化临时凭据。

完成确认后调用共用绑定接口，再重新读取权威 settings；不得用向导开始时的 settings 整体覆盖。已有连接时「保存」只新增配置，「保存并切换」再执行安全激活；首次默认后者。绑定已保存但激活失败时保留新连接并明确提示，不能误报完整成功，也不能重复新建。后端返回已存在的目的地时使用该稳定 ID；账号不兼容或有待处理工作时遵守既有拒绝规则，不静默覆盖会话。

无 Space 时仅提供显式创建或取消，不隐式创建。显式创建成功后取消向导不会自动删除远端 Space，需要向用户说明它已在服务端创建。创建能力必须先通过关联变更的检查门槛，再接入。

备选是先保存半成品 profile 或沿用全屏 onboarding 的活动状态，分别会留下未确认配置或污染当前账号，故不采用。

### 4. 安全激活使用最新配置和统一转换

激活链路固定为：安全结束当前编辑/发送上下文 → 将富文本编辑器序列化并保存原范围草稿 → 后端校验最新目标配置并提交活动 ID → 停止旧目标的新业务调度 → 重新初始化目标视图。不能安全结束的发送、保存或系统文件选择阻止转换；只是存在离线队列不阻止切换。

选择共用的、仅修改活动 ID 的后端操作，复用现有 profile 校验与同步重置信号；若现有共用接口不满足语义，则增加窄化的激活命令，而不是在移动端拼装整份 `saveSettings`。后端在受控设置更新内校验目标存在、Provider/启用状态及绑定状态，并确保与移除、禁用等配置操作有一致的并发顺序；目标已删除/禁用返回错误。未登录的有效绑定目标可进入登录页，但不启动业务同步。

提交前失败保持旧 ID；提交成功后目标加载失败则显示目标的错误恢复页，不伪装回到旧配置。旧请求的 generation 在转换边界失效，覆盖账号查询、消息/标记分页、草稿读写、媒体下载、原生文件选择和状态诊断。业务请求携带原 profile/账号/Space，晚到结果只可安全写回原范围或丢弃，绝不重新解析为当前目标。

原连接的缓存、checkpoint、会话及队列保留；暂停旧同步的新调度，在途写入若无法取消则仍只完成于原目标。返回原连接恢复原范围草稿及队列。启用/禁用、退出和移除也复用相关转换保护，不另写一套不一致的前端判断。

备选是沿用旧 settings 快照整体保存，可能丢掉并发配置；或把所有 pending work 当作禁止切换条件，会破坏离线本地优先能力，均不采用。

### 5. 更换目标、启停及移除明确区分

| 操作 | 配置/会话影响 | 本地与同步影响 | 保护 |
| --- | --- | --- | --- |
| 切 A → 已保存 B | 只改变活动 ID，不退出 A | 保留 A 的镜像、草稿及队列 | 先保存草稿，防在途串范围 |
| 改名称 | ID、目标、会话不变 | 数据不变 | 窄化更新，重新读取配置 |
| 改地址/Key | 目标变更，不能直接复用旧认证结论 | 有业务数据/待处理工作时拒绝覆盖 | 引导新增，空连接也重新验证绑定 |
| 同 profile 重绑 Space | 保留 profile ID 和合法会话 | 沿用重建旧镜像/游标语义，远端保留 | 权限验证、待处理检查、草稿/附件处理、独立确认 |
| 启用非活动连接 | 不自动激活 | 不启动它的业务同步 | 校验最新配置 |
| 禁用当前连接 | 保留会话，活动 ID 置空 | 保存草稿，保留队列并停止新调度 | 不能安全结束时拒绝，不自动选其他 Provider |
| 移除连接 | 删除配置及对应安全会话 | 远端不删，保留本地历史不重归属 | 默认非强制；当前/最后一个及放弃工作需明确确认 |

普通移除先使用非强制后端调用；当前连接引导先切换。用户选择清空当前/最后一个或明确放弃待处理工作时，使用受控强制路径，展示被放弃的队列、冲突和传输影响，不能以一个默认确认绕过保护。草稿先保存在原范围；不能保留则阻止操作。移除不能把残留历史自动映射到后来新增的连接。

更换 Space 是已有危险边界，新增连接管理不弱化它。草稿及本地附件不一定属于业务 pending 检查，需单独检测；不在本次创造自动导出或迁移方案，无法安全保留时要求用户先发送、清理或取消。

备选是所有操作统一走一次设置保存，或在移除确认后总传 `force: true`，会混淆不同数据后果，故保留分别验证的操作语义。

### 6. 会话与诊断保持指定连接归属

保存、登录、退出和刷新均显式指定 profile ID；服务地址相同也不能共享会话或以最后登录账号覆盖其他 profile。不同账号登录遵守既有 pending 防护，历史读取和草稿始终包含账号/Space 范围。

管理页按需调用指定连接的只读连通性、当前用户和 Space 检查；诊断可刷新该连接的合法会话，但不能激活连接、启动 outbox、业务补拉或 Realtime。状态结果按 profile ID 与配置修订归属，区分网络未知和明确认证/绑定拒绝，不为显示卡片而频繁全量刷新。Token、密码与 Key 内容不记录到日志和错误；公开 Key 虽非会话秘密，也不在列表回显。

备选是激活连接后借启动流程诊断，会改变活动状态并触发业务读取，故不采用。

### 7. 关联变更采用契约检查门槛

开始实现时对 `defer-supabase-space-creation` 逐项核验：临时 flow 取消/到期及参数失效、最终 Space 权限验证、无隐式创建、显式创建、统一绑定入口保护与安全重绑。明确哪些代码已实现、哪些测试已通过及哪些任务仍待完成；存在 API 不等于上述契约成立。

缺失的共享后端/SQL/迁移任务保持原变更归属，作为依赖先完成并验证，本变更负责移动端接入、profile 激活和多连接交互/隔离测试。统一绑定状态由关联变更提供，不在移动端另建持久字段或猜测状态；其旧数据迁移不重复实施。该门槛不要求关联变更所有无关 UI 任务完成，但共享安全契约不完整时不进入对应绑定或真机验收。

备选是复制移动端专用绑定后端，会制造两套 Space 行为且难验证迁移，故不采用。

## Risks / Trade-offs

- [共享绑定能力尚未完整落地] → 以代码与测试核验依赖，不根据计划标记完成；缺失项先按原任务归属实现。
- [旧异步回调覆盖新连接] → 请求携带范围和代次，对原生回调、媒体与诊断加入延迟回放测试。
- [保存配置成功但安全会话或激活失败] → 绑定接口验证补偿/幂等结果，前端读取权威结果；单独说明「已保存、未切换」，允许安全重试。
- [离线无法确认账号/绑定] → 不清除本地会话或误判退出；已知有效绑定可以使用本地缓存，联网后再诊断。
- [原位 Space 重绑清理旧镜像] → 明确说明并确认，有 pending、冲突、传输或未处理草稿/附件时阻止。
- [移除后仍占用本地历史空间] → 保留既有非删除语义，本次不增加缓存清理；说明「移除连接」不等于删除远端或本地历史。
- [显式创建 Space 后取消向导] → 远端创建不回滚，告知结果，不自动删除远端数据。
- [仅同服务两个 Space 不能证明多地址隔离] → 可控测试使用两套独立 endpoint，最终用两个授权 Supabase 服务地址分别验证；缺少授权环境时真实多服务端验收保持未完成。
- [VPhone 可用性和原生签名不同于正式设备] → 官方 Simulator 为日常必测，VPhone 为可选第二环境，最终以实际 iPhone 验收为准。

## Migration Plan

1. 审计共享绑定契约和现有测试，先处理必要依赖；本变更不迁移 profile ID 或会话命名空间。
2. 增加窄化的安全激活/配置转换与失败回归测试，保留桌面设置和接口兼容。
3. 将移动端状态拆分为全部配置、活动状态和临时向导，接入卡片页、快捷选择及恢复入口。
4. 接入新增/编辑、会话诊断、启停和安全移除，替换混淆 profile 与 Space 的入口。
5. 执行类型检查、前端/后端测试及构建；在 Simulator 验证所有异常流程，再按可用性补充 VPhone，在真实 iPhone 完成最终验收。测试只使用授权普通账号和专用空间，不写入生产消息，不硬编码设备或凭据。
6. 补充移动端使用和测试文档，记录真实双地址验收证据与仍未执行项目。

回滚只恢复旧移动端入口，保留原 profile、会话和本地范围数据；新增连接仍可由兼容 profile 模型读取。不得通过回滚恢复隐式 Space 创建或绕过绑定保护，也不删除用户明确创建的远端 Space。
