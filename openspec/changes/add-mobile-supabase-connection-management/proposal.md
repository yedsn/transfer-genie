# Proposal

## Why

移动端目前主要围绕当前 Supabase 账号内的 Space 展示，缺少 PC 端已有的多连接管理入口；当前连接退出登录或异常时，用户也难以切换到其他已保存连接。需要在保持 iOS 本地优先和数据隔离的前提下，补齐多个 Supabase 连接的配置、管理和切换能力。

## What Changes

- 在「我的 → 存储空间」提供移动端全屏卡片管理页，展示所有已保存的 Supabase 连接，包括禁用、未登录和异常连接，支持新增、编辑、启停和移除。
- 首页顶部提供轻量快捷切换入口，以已保存连接为选择对象；当前连接内的远端 Space 选择作为独立的配置/修复流程，不与连接切换混用。
- 首次配置与新增连接复用「连接 → 账号 → 空间 → 确认」向导，新增草稿和临时登录状态独立于当前连接，可返回、取消，保存后可选择是否切换。
- 按连接保存登录状态，按连接、账号和远端空间隔离消息、标记、草稿、附件、同步队列与游标；切换已保存连接保留原缓存及待同步工作，不退出原账号、不自动复制或合并数据。
- 明确编辑目标地址、重绑远端 Space、禁用当前连接和移除连接的安全边界，避免静默丢弃草稿或待同步数据。
- 无配置、未登录、绑定异常和初始化失败时仍可进入管理或选择其他连接；移动端继续只提供 Supabase，不增加 WebDAV。

## Capabilities

### New Capabilities

无。复用现有存储配置、隔离与 Supabase 能力，不另建连接模型或同步引擎。

### Modified Capabilities

- `client-settings`: 增加移动端多连接卡片管理、可取消的配置向导、编辑保护及异常状态下的管理入口。
- `storage-profiles`: 增加移动端快捷连接切换、草稿及异步结果隔离、连接启停与安全移除行为。
- `supabase-storage`: 增加移动端多连接会话管理、非活动连接检查及绑定流程的临时会话隔离。

## Impact

- 前端主要涉及 `src-ui/src/mobile/MobileShell.vue`、`mobile-controller.ts` 与共用 Tauri API 封装；PC 交互不改版，既有桌面配置不得因移动端保存而丢失。
- 后端复用 `StorageProfile`、系统凭据库、绑定流程及 profile 增改/移除接口；必要时补齐统一的激活和安全状态转换保护，不新增平行持久化结构。
- 与未完成的 `defer-supabase-space-creation` 变更共享绑定契约：实现前核验显式 Space 选择/创建、取消和重绑保护，缺失部分按原变更归属衔接，不将计划中的能力当作已完成。
- 增加多连接隔离、离线切换、晚到回调、取消向导及移除保护测试；验收顺序为官方 Simulator、可选 VPhone、真实 iPhone，实际多服务端验证需要两个授权的 Supabase 地址。
- 不涉及跨连接导入、全连接后台同步、WebDAV、Supabase 数据库架构重设计或分发签名方式变更；本提案阶段不修改应用代码、不操作远端数据。
