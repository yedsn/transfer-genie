# Change: 插件机制、多选引用与图片下载机器人

## Why
用户需要在 TransferGenie 安装可扩展机器人，通过聊天中的 @ 和多选引用，把图片下载任务交给指定 PC。现有内置集成模块支持状态与进程管理，但尚无用户可安装插件、结构化引用或机器人任务路由。

## What Changes
- 增加版本化插件说明、目录/ZIP 安装、配置、启停、日志、卸载及设置页插件管理。
- 插件按能力注册入口，首期实现 bot 能力，保留未来消息操作等能力的扩展位置。
- 支持一次性执行和常驻进程两种运行方式，安装登记能力不启动程序。
- 增加同一存储空间的单条及多选引用、引用摘要和原消息定位。
- 增加结构化 @ 目标选择、跨设备实例目录、可靠任务投递和逐项结果。
- 提供可安装的图片下载机器人，支持引用图片附件与图片直链，默认保存到执行设备系统下载目录，可在插件设置中修改。
- 桌面端执行插件；手机端支持引用、调用和查看结果，不运行桌面脚本。
- 扩展本地与 WebDAV/Supabase 同步数据，保留旧消息兼容；远端新字段/记录需对应迁移与版本识别。

## Impact
- Affected specs: plugin-system（新增）、message-references（新增）、bot-tasks（新增）、image-download-bot（新增）。
- Affected code: Rust 插件宿主、integration_runtime、workspace、types、db、history、存储 Provider 和同步；src-ui 设置、桌面/移动消息流及输入框；Supabase 迁移、插件包及发行配置。
- 首期包含内置/外置插件分类、本地导入和基于索引的插件市场下载；不包含任意网页图片抓取、AI 指令解释和关闭 TransferGenie 后独立常驻的服务宿主。
- 外部插件按当前用户权限执行；配置与能力声明不等于操作系统沙箱。

## Acceptance
在 PC 安装启用图片插件，手机在同一空间多选图片并 @ 该实例，PC 自动保存原件到系统下载目录，聊天收到逐项成功/失败结果；重复同步、重启恢复与部分失败重试不重复保存成功项。

## Review Status
提案待用户评审。当前仅记录设计与任务，应用代码未实现。

## OpenDock Reference Update
- 参考 OpenDock 的 plugins/.system、统一插件管理、内置不可卸载、外置可卸载，以及独立索引市场模式。
- 图片下载机器人改为随应用发布的内置插件，自动出现在已安装列表，默认停用；启用后使用系统下载目录。内置来源与外部进程运行方式相互独立，仍采用通用机器人协议。
- 外置插件支持目录/ZIP 导入和市场下载，两条路径复用完整包校验与安装流程，记录来源及版本。
- 市场首期支持可配置 index.json、平台/架构匹配、下载进度、SHA-256 校验和显式更新；准备可验证的本地市场 fixture 与索引发布模板。正式市场地址在实际提供后配置，不复用 OpenDock 市场或编造可用 URL。
