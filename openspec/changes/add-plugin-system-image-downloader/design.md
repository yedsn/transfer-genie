## Context
项目实际前端为 src-ui（Vue/Vite），后端核心位于 src/lib.rs。integration_runtime.rs 已提供内置模块状态，telegram_bridge_runtime.rs 已提供进程生命周期，workspace.rs 已提供 plugins 目录。它们是实现基础，不能直接视为动态插件系统。消息经 SQLite/outbox 在独立 WebDAV 或 Supabase 空间同步，引用与机器人记录必须覆盖两种 Provider。

## Goals / Non-Goals
- Goals: 用户可管理外部插件；机器人可按需或常驻运行；手机可调用指定 PC；批量引用原件下载；故障可观察且恢复不重复产生已完成文件。
- Non-Goals: 本期不提供任意前端代码注入、AI 调度、网页爬图、跨空间引用、分布式抢单或脱离桌面应用的宿主。插件市场仅做索引浏览、完整包安装和更新，不做账号、支付、评分或下载量服务。

## Decisions

### 1. 插件包与注册
plugin.json 使用 manifest_version、id、name、version、host_api_version、supported_platforms、capabilities、runtime、config_schema。id 在本机唯一，未知能力保留但不激活。bot 能力声明输入类型、批量支持和操作。runtime 声明 mode（oneshot/service）、command、args、工作目录、启动策略及所需运行环境。

目录与 ZIP 安装均复制到受控的 workspace/plugins/<plugin-id>/versions/<version>，配置、日志和任务数据与版本目录分开。校验包大小、路径穿越、符号链接、平台和接口版本；入口必须在安装目录内，声明的外部解释器通过明确依赖查找。禁止安装任意脚本钩子。安装只登记；配置完成后启用并注册实例。缺少依赖时显示原因且拒绝任务。重复 id 安装走显式替换/升级，先停止进程，校验新版本后切换，失败保留旧版本。内置模块 id 受保护。

机器人实例 id 为本机持久化 UUID，绑定插件 id、设备 id 及配置，不以显示名称路由。同一插件首期每机一个实例，重新安装可恢复原身份；不同机器实例不同。

### 2. 插件协议与生命周期
使用带 protocol_version、request_id、task_id 的 JSON Lines stdin/stdout 协议；stderr 为日志。宿主显式传递参数，避免拼接 shell 指令；Windows 子进程隐藏窗口。协议支持 ready、invoke、progress、result、cancel、shutdown 和附件读取请求，规定消息大小及超时。

oneshot 每次任务启动进程，输出终态后退出；service 启动时完成 ready 握手后接收任务，可按调用或随应用启动。正常 idle 不算错误，ready 未完成不能投递。任务 result 与进程退出码共同决定结果；协议破损、崩溃、无响应显示具体错误。常驻进程使用有上限的退避恢复，避免无限重启。取消、停用、卸载及应用退出先请求停止，再在超时后终止所管理进程树。

设置页分别显示安装/启用、环境就绪和进程/任务状态；oneshot 显示“按任务运行”，service 提供启停与启动策略。配置由受支持的 schema 字段渲染。版本、设置、日志、逐项任务记录和卸载入口均可访问。密钥保存在本机凭据存储且日志脱敏。普通外部进程不是沙箱，界面准确说明运行权限。

### 3. 多选引用与调用消息
输入草稿保存 references 数组，元素为同空间稳定消息标识、发送者/类型、文本摘要、附件标识。没有 message_id 的 WebDAV 旧消息使用空间内稳定文件标识，不仅依赖临时 UI 索引。按消息时间、稳定 id 排序并去重，首期上限 50 条；桌面与手机支持单选、多选、展开和移除，切换空间不会把引用带入另一空间。

发送时保存引用关系与显示快照，引用预览点击定位原记录，已删除显示不可用。任务输入固定发送时的文本和附件版本/哈希，显示摘要不能替代完整输入。附件原件按需下载，不因引用而复制上传。若原版本不再可读取，该项失败，不以更新后的文件替换。

@ 通过候选选择保存 target_bot_instance_id，展示名字/设备/状态；字符串中偶然出现 @、粘贴日志和机器人输出不会创建任务。首期每次调用选择一个机器人，可输入图片直链或引用多条消息。普通引用消息不创建任务。

### 4. 跨设备目录与可靠投递
只在用户为插件启用的空间发布实例目录：实例 id、插件能力版本、名称、设备、平台、可用状态、心跳和失效时间。安装包、绝对保存目录和密钥不发布。同账号/空间现有权限控制目录与任务；旧客户端看见正常文本摘要但不会执行控制记录。

采用版本化的独立 bot-directory、bot-task 和 bot-event 控制记录，消息保存 references、target 和 task 关联。WebDAV 使用独立控制路径与稳定事件文件，Supabase 使用对应表/RPC 与空间 RLS，不把调度状态塞进普通历史文本。所有控制写入先进入本地事务/outbox，再经 Provider 同步。实现前明确字段、迁移、旧版本读取兼容及变更能力协商。

发送端原子保存调用消息和任务快照，task_id 稳定；执行端只接收绑定自身实例的合法调用任务，以空间/账号/task_id 唯一约束记录领取。每项 item_id、输入哈希和结果持久化。状态为 waiting_device、queued、running、succeeded、partial_failed、failed、cancelled、expired、interrupted；离线等待默认 24 小时到期。目录在线状态为心跳推测，不承诺立即执行。

任务更新以不可变事件和序号同步，仅任务发起方可请求取消/重试，执行方报告进度/结果；Supabase RPC/RLS 校验身份，WebDAV 使用现有可信空间成员模型，不声称提供独立成员隔离。终态回复使用稳定消息 id，重放不重复回复。任务修改消息不重新触发；重试为显式请求。

普通插件崩溃后的未知副作用不能承诺 exactly-once，标为 interrupted，交由用户决定重试。图片插件支持逐项恢复：目标路径和内容哈希在落盘前记录，临时文件完成后原子发布；重启检查既有文件哈希，恢复已完成项，缺失项才重做。部分失败仅重试失败项。

### 5. 首个图片机器人
以随应用提供的内置插件交付，发行时包含本机平台的独立 Rust 可执行程序与 manifest，自动出现在已安装列表，默认停用。它遵循同一协议，不通过宿主中的特殊下载分支绕过插件机制，且不依赖用户另装 Python/Node。其他脚本插件仍可声明解释器依赖。内置指交付来源，不代表在主进程中执行。

插件配置 download_dir 默认为目标设备系统下载目录，通过系统 API 解析，不硬编码 Downloads。未找到目录时要求选择，不静默写入工作目录；机器人名称默认“图片下载”，用户可改。仅保存到本机并回传文件名/结果，首期不自动把结果再上传。

支持被引用的图片附件，以及指令/引用文本中的 HTTP(S) 图片直链。宿主校验空间权限、取得原件并提供任务专用暂存路径，不给插件 Provider 凭据；链接由插件流式下载。第一版不抓取网页中的图片、不使用 AI 解析命令。图片通过内容签名和受限解码探测确认，不能只信扩展名/Content-Type；默认每项 100 MiB、至多 5 次重定向、30 秒无数据超时、单项总时限 10 分钟、并发 2，可通过宿主受控设置调整。

文件名清洗路径字符和 Windows 保留名，不接受输入任意保存路径，不覆盖已有文件；同名内容不同添加序号，恢复任务复用既定路径。临时文件仅在目标目录内创建，成功后原子发布，失败清理。插件返回 item_id、来源、状态、最终文件名、大小、哈希、保存位置或错误；宿主聚合回复，其他设备不能把 PC 本地路径当可下载附件。

### 6. 兼容与平台
新元数据为可选字段，旧消息默认空引用/无任务；新客户端读取旧记录正常。Supabase 迁移及 RPC 同步部署后才启用相关空间调用；WebDAV 先发布协议能力版本。迁移失败不得破坏已有发送和同步。

Windows/macOS 支持执行，移动端只发布调用和查看结果。应用退出停止托管任务，重启后按插件恢复策略处理。保留未来独立宿主协议边界，本期不安装系统服务。

## Risks / Trade-offs
- 插件可访问当前用户系统资源：明确来源与权限，不把 manifest 当隔离机制。
- 两种 Provider 需要控制记录同步：复用可靠队列，但独立验证权限、重放和断网恢复。
- 文件发布与数据库提交不是单一事务：使用持久化目标、哈希与恢复检查弥补间隙。
- 删除的远端原件不能保证一直可用：引用快照保留摘要，任务返回逐项不可用。
- 已有移动恢复/空间创建变更仍进行中：实现时避免改写其流程，以兼容字段与独立模块接入。

## Migration Plan
1. 先完成本地版本化表结构、引用兼容和插件协议。
2. 部署 Supabase 增量迁移/RLS/RPC，并完成 WebDAV 控制记录协议与能力检测。
3. 接入管理 UI、跨设备任务与外部图片包，按验收矩阵检查。
4. 回退时停用插件与控制记录消费，保留本地配置/任务和新可选字段；普通消息继续使用原同步。

## Open Questions
- 本提案默认首期同时支持 WebDAV 与 Supabase 跨设备调用，是否需要缩小 Provider 范围可在评审时调整。
- 独立后台宿主及结果自动上传作为后续变更；正式市场托管地址尚未指定，客户端先支持配置来源和本地 fixture 验收。

## OpenDock Reference and Revised Distribution
参考本机 OpenDock/plugins/registry.ts、src-ui/src/components/settings/PluginsPanel.vue、src-ui/src/store.ts 的市场流程，以及 docs/guide/plugin-marketplace.md。实际 registry 使用构建期 glob；市场安装目前主要取得 plugin.json 并登记声明式贡献，没有完成文档所述的全部源码/Release 包安装链路。TransferGenie 不假定直接复用它即可运行外部机器人，也不承诺 OpenDock 插件包兼容。

### Builtin / External
插件 source_kind 为 builtin/external，origin 为 bundled/local_import/marketplace，与 capability 和 runtime.mode 分开。内置源位于仓库 plugins/.system/<id> 并作为只读应用资源发布，用户配置、任务和日志位于应用数据目录。外置版本位于 workspace/plugins/<id>/versions/<version>。内置插件仅启停，不可卸载、被外置同 id 覆盖或被市场更新；随应用升级更新。已有 WebDAV/Telegram 内置模块可通过适配器统一展示，不在本次重写核心同步为外部插件。

内置与外置共享 manifest、能力注册、配置与任务协议。内置来源由宿主资源清单确定，不能相信导入 manifest 的 builtIn 字段。停用后入口从可调用列表移除，保存配置；若插件设置页已失效则回到管理页。

### Market and Local Import
管理页包含“已安装”和“插件市场”，提供导入插件包/目录。已安装条目标注内置或外置、来源、版本、启用与运行状态；外置支持卸载，市场插件显示可更新。

市场使用独立 index.json（schemaVersion、插件 id/名称/描述/作者/分类/能力、最新版本、最低宿主版本、版本清单链接）。版本清单按 OS/architecture 列出 ZIP URL、大小及 SHA-256。首期统一使用完整 ZIP 产物，不逐个下载源码文件，不动态导入市场 Vue/TS 代码。索引可缓存并手动刷新，离线不影响已安装插件。来源为可配置 HTTP(S) 地址，可设置镜像；默认来源仅在有实际托管地址时启用，未配置显示说明而非虚构市场内容。

本地导入与市场下载共用暂存、校验、解压、依赖检测和原子安装器。下载完整二进制包，校验 SHA-256、manifest id/version/platform 与索引一致后才激活；哈希只证明与当前索引一致，不等于作者身份认证，不显示没有审核依据的认证标记。失败清理暂存并保留旧版本。更新由用户触发，不自动运行新版本；配置继续保留，兼容性失败可回滚。市场无相应平台包时禁用安装并说明原因。

准备包含一个外置协议示例插件的本地 HTTP 索引/ZIP fixture，验证市场端到端流程，以及可发布的索引规范/模板；创建远端仓库或发布市场不包含在当前授权中。
