# Proposal

## Why

移动端启动会等待当前 Supabase 账号检查；服务器迟迟不响应时，用户持续停留在没有恢复操作的 loading 页面，无法切换已保存的存储空间。需要让启动等待有明确上限，并让用户在等待及异常时都能进入现有连接管理流程。

## What Changes

- 启动初始化设置 10 秒前台等待上限，明确失败立即结束 loading，超时显示连接超时提示。
- 本地配置读取完成后，在 loading 页面提供“切换存储空间”和“管理存储空间”；异常页提供明确原因、重试、切换及管理入口。
- 离开等待页、重试或切换连接时使旧初始化结果失效，防止晚到回调覆盖新页面或新连接。
- 为启动账号验证及必要的会话刷新增加有界网络等待，保留网络异常与明确登录失效的既有区别。
- 复用现有连接选择与管理能力，不强行进入依赖账号和草稿恢复的主界面。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `client-settings`: 补充移动端启动等待上限、等待期间的存储空间恢复入口、错误分类和旧启动结果隔离要求。

## Impact

- 前端主要涉及 `src-ui/src/mobile/mobile-controller.ts`、`MobileShell.vue` 及对应移动端控制器和浏览器测试。
- 后端涉及 `src/lib.rs` 的启动账号验证链路及必要的 `src/supabase_auth.rs` 请求边界；不对共享 HTTP 客户端设置影响大文件传输的全局总超时。
- 衔接 `add-mobile-supabase-connection-management`：复用已实现的选择、管理和安全激活，本变更承担挂起请求、启动截止时间及等待中退出的缺口；不修改该变更已有任务完成状态。
- 无新增依赖、数据库迁移或远端结构变更；不扩大到桌面启动改版、完整离线主界面或后台多连接同步。
