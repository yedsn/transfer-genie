# Design

## Context

动机见 proposal.md。`initialize()` 在读取本地配置后等待 `supabaseCurrentUser()`，之后恢复草稿才置为 ready；loading 模板无恢复按钮，已有 error/choose-profile 页面和 connection-manager 可复用。`verified_supabase_session()` 对部分网络错误可沿用本机会话，但须等待远端请求先结束。共享 HTTP 客户端只显式限制建连时间。现有 viewGeneration 能隔离不同初始化结果，尚需覆盖主动离开等待页及超时。

`add-mobile-supabase-connection-management` 已实现连接管理及普通初始化错误恢复。本变更只补充等待上限与等待期间的退出保护；独立使用新 requirement 名称，避免与该变更的待归档规范互相覆盖。

## Goals / Non-Goals

**Goals:** 网络检查、配置读取和草稿恢复均不能无限阻塞启动；用户从等待页可进入已有恢复流程；恢复操作不被旧异步结果打断。

**Non-Goals:** 不增加离线身份模型，不跳过权限检查开放发送，不为传输请求添加全局短超时，不重做连接管理或原生导航。

## Decisions

### 1. 前端以每轮初始化的截止时间控制 loading

从 initialize 入口记录 10 秒截止时间和请求代次，终态统一清理定时器。超时使本轮失效并进入恢复页；前台恢复时核对截止时间，解决后台定时器暂停。所有 await 后和 catch/finally 中的界面提交均检查代次；下层草稿恢复等内部写状态也需核验，不能只防护外层 await。计时只覆盖进入 ready 前的必要准备，不覆盖 ready 后本地列表刷新和后台同步。

仅在后端添加超时不能覆盖本地 IPC 或其他启动步骤；仅 Promise.race 不能阻止原任务晚到写状态。因此前端期限与代次隔离同时实施。

### 2. 等待页与恢复页共用现有连接入口

配置可用后展示“切换存储空间”“管理存储空间”；用户触发时先使旧初始化失效、结束其计时，再打开已有选择页或管理页。打开选择不等于激活，仍由既有安全激活接口提交目标。关闭管理页或取消选择后回到可操作的恢复/选择状态，不回到已失效的 loading；需要继续原连接时由用户重试。尚未取得配置时保留重试并准确报告本地读取问题。

明确网络失败提示“存储空间连不上”，超时使用规范中的文案；登录失效继续引导登录，绑定异常继续修复。错误详情使用现有脱敏错误转换，产品文案统一使用“存储空间”。

直接进入主界面需额外设计离线身份、草稿就绪与发送权限，本次使用用户已接受的恢复页方案。

### 3. 后端仅收紧启动认证请求边界

为启动调用的账号验证及必要会话刷新增加整体有界等待，覆盖发送和读取响应体；建议启动认证链路总预算 8 秒，为前端 10 秒期限留出返回余量。限制应通过启动专用路径或显式可选预算传递，避免误伤共用认证及大文件传输；若新增 API 参数，保持已有调用兼容。超时映射为网络错误，保留既有网络异常会话回退及刷新失败策略；只有明确失效证据才撤销会话。

前端离开页面并不自动取消已发出的 Rust command。旧请求仍可在原 profile 下正常完成认证维护，但不得改变活动 profile 或其他账号状态，且必须受后端预算限制；前端忽略它的界面结果。

## Risks / Trade-offs

- 慢网络可能在 10 秒内无法完成 → 提供显式重试和切换，不清除本地工作。
- 超时与成功同一时刻发生 → 由同一轮有效性检查保证只提交一个终态，并测试边界竞争。
- 管理页被晚到结果关闭、旧草稿串入新空间 → 入口先失效旧轮，覆盖内部异步写状态和旧定时器。
- 改共用认证语义影响桌面 → 请求预算局限启动路径，回归网络回退与明确撤销测试。

## Migration Plan

无数据迁移。先补控制器及网络挂起夹具，再接入恢复 UI；执行类型检查、构建、相关前后端测试与 cargo test，最后在官方 iOS Simulator 检查启动超时、管理及切换流程。设备不可用须记录未验收，不能以浏览器结果代替。回滚代码即可，不清理配置、凭据或缓存。
