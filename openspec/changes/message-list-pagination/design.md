## Context

当前首页消息流已经具备分页基础能力：前端 rontend/main.js 使用 PAGE_SIZE = 10 调用 Tauri 命令 list_messages_window，后端 src/main.rs 和 src/db.rs 已支持三种窗口查询模式：
- 默认查询最新一页
- 基于最旧消息边界向前查询更早消息
- 基于最新消息边界查询新消息

同时，前端也已经维护了 hasMoreMessages、isLoadingMore、oldestLoadedMessageRef、
ewestLoadedMessageRef 等状态，并在消息列表滚动接近顶部时触发 loadMessages({ loadMore: true })。

因此，这次变更不是新增后端分页能力，而是要把首页体验明确收敛为“首屏仅加载最后一页 + 顶部自动续载上一页”，并把该行为固化为产品能力和实现约束，避免再次回退到全量加载。

## Goals / Non-Goals

**Goals:**
- 首页首次打开或手动刷新时只展示最新一页消息，而不是历史全量消息。
- 用户向上滚动到消息列表顶部附近时，自动加载上一页历史消息。
- 加载历史消息后保持当前阅读锚点，避免滚动位置跳动。
- 保持现有“检查新消息”机制，确保新消息仍能追加到列表底部。
- 将该行为写入 message-feed 规格，作为后续实现和回归验证依据。

**Non-Goals:**
- 不修改后端数据库结构或分页 SQL。
- 不引入页码式 UI、跳页器或独立分页控件。
- 不改变已标记消息页、下载页、上传页的现有分页方式。
- 不处理消息搜索、筛选或虚拟列表渲染优化。

## Decisions

### 1. 复用现有窗口分页接口，不新增后端 API

决策：继续使用现有 list_messages_window 命令作为首页消息分页接口。

原因：
- 后端已经支持“最新窗口”“向前翻页”“向后检查新消息”三种查询模式。
- SQL 层已按时间倒序截取后再升序返回，天然满足聊天流“最新在底部”的显示要求。
- 避免为同一能力引入重复 API，降低维护成本。

备选方案：新增专门的 list_home_messages 命令。
未采用原因：能力重复，没有额外收益。

### 2. 首页首屏行为以“最新窗口”为唯一基线

决策：首页首次进入、切换 WebDAV 端点、手动刷新时，都从 list_messages_window({ limit: PAGE_SIZE }) 开始，只加载最后一页。

原因：
- 这与用户对聊天应用的预期一致，默认先看到最新消息。
- 可显著降低大消息量场景下的初始渲染成本。
- 便于与定时“检查新消息”逻辑复用同一组边界状态。

备选方案：按总量动态决定是否全量加载。
未采用原因：行为不稳定，且会让性能问题在高消息量场景再次出现。

### 3. 顶部自动加载采用滚动阈值触发，而非显式按钮触发

决策：保留并规范当前基于滚动位置阈值的自动加载机制，在消息列表接近顶部时触发 loadMore。

原因：
- 聊天历史向上续载是更自然的交互方式。
- 现有代码已经具备滚动监听、去抖和加载状态控制，改动最小。
- 比单纯依赖“加载更多”按钮更符合用户提出的预期。

备选方案：仅保留顶部按钮，取消自动触发。
未采用原因：与需求不符，用户需要“滚动到顶部自动加载”。

### 4. 历史消息插入后必须保留视觉锚点

决策：加载上一页后，新消息批次插入列表头部，同时通过已有 preserveScroll 逻辑修正 scrollTop，让用户继续停留在原先阅读位置。

原因：
- 若直接 prepend 而不补偿滚动，视口会突然跳动，影响阅读。
- 当前代码已有滚动补偿逻辑，应将其视为必需行为而非偶然实现。

备选方案：每次加载后滚动到新批次顶部或底部。
未采用原因：都会打断用户正在阅读的上下文。

## Risks / Trade-offs

- [滚动阈值过于灵敏] → 可能重复触发加载；通过 isLoadingMore 和去抖逻辑限制并发请求。
- [首屏仅加载最后一页后，旧消息不可见] → 这是有意 trade-off，用自动续载补足浏览路径。
- [定时检查新消息与历史续载并发] → 继续复用现有边界状态管理，避免覆盖已加载历史窗口。
- [DOM 列表继续增长] → 本次只解决首屏全量加载问题，不处理超长会话的虚拟化，后续如有性能瓶颈再单独立项。

## Migration Plan

- 更新 message-feed 规格，明确首页消息流的分页和自动续载要求。
- 更新前端首页消息加载与滚动交互实现，确保所有入口都以“最新一页”初始化。
- 通过手动验证确认以下场景：首次进入、切换端点、手动刷新、顶部自动加载、定时新消息追加。
- 若上线后发现滚动触发体验不稳定，可仅回退前端触发策略；后端接口无需回退。

## Open Questions

- 当前默认页大小是否长期固定为 10，还是后续需要做成配置项；本次先沿用现有常量。
- Vue 壳层与原生 DOM 壳层是否都完全走同一消息流渲染路径；从现有代码看主要状态仍由 main.js 统一驱动，本次按统一路径设计。
