# Design

## Context

当前首页工具栏直接提供“打开下载目录”，文件下载主要从单条消息触发。后端 `download_message_file` 已具备下载目录解析、命名规则、同名处理、流式下载、断点续传、进度事件、消息本地路径更新和下载历史记录；现有下载页能够展示进行中及历史任务。消息索引已经保存资料查询所需的文件名、原始名称、消息类型、大小、时间、远端路径、转写来源和源音频类型。

本变更需要横跨首页、模态交互、SQLite 查询和下载任务编排，但不得改变 WebDAV history 格式或复制一套新的文件传输实现。参见 `proposal.md` 和 `specs/bulk-download-dialog/spec.md`。

## Goals / Non-Goals

**Goals:**

- 让大量资料的浏览、筛选和选择保持流畅，并保证不同视图共享同一份查询、分页和选择状态。
- 把复杂的刷选、框选和跨页全选行为封装为独立于具体视图的选择模型。
- 复用现有单文件下载执行路径，并用有限并发队列扩展为批量下载。
- 保持现有下载历史、断点记录、进度事件和下载页的兼容性。

**Non-Goals:**

- 不把弹窗变成完整文件管理器，不提供远端移动、重命名或删除功能。
- 不在第一版生成视频封面、音频波形或媒体时长。
- 不让待执行的批量队列跨应用重启恢复；已经开始的文件仍可使用现有部分下载记录续传。
- 不修改 WebDAV 目录结构、history 格式或现有单条消息下载入口。

## Decisions

### Decision: 使用独立的大型模态组件而不是复用下载任务页

批量下载是“选择远端资料”的临时工作流，下载任务页是“观察已经提交的传输”的持久工作流。弹窗放在首页顶层，使用与现有全屏预览相同的遮罩层级，但采用独立的固定头部、可滚动内容区和固定底部操作区。提交后关闭弹窗，并把观察职责交给现有下载页。

替代方案是在下载页加入资料库二级页签；该方案会把快捷操作变成页面导航，与已确认的首页入口和弹窗体验不符。

### Decision: 后端提供专用的分页资料查询和轻量全选解析

新增资料查询输入，包括分类、格式、搜索词、页码和每页数量。查询直接基于 SQLite 消息索引，按 `timestamp_ms DESC, filename DESC` 稳定排序，并返回当前页项目、总数、分类统计、可用格式及下载状态摘要。分类依据原始文件名扩展名统一映射；语音转写记录转换成关联源音频资料，普通文本不进入结果。

“全选全部筛选结果”不逐页拉取完整卡片，而是调用轻量解析查询，只返回匹配资料的稳定键和大小。前端把这些键加入显式选择集合，因此选择结果在用户点击全选时即被冻结，不会因为随后同步到新的资料而意外扩大。

替代方案是在前端加载全部消息后分类分页；该方案会增加弹窗启动成本，也无法稳定支持大量资料和准确统计。服务端临时选择令牌也被放弃，因为会引入生命周期、失效和清理机制，而本地轻量键集合足够简单。

### Decision: 使用统一的资料视图模型驱动五种布局

五种查看方式共享一个资料视图模型，包含稳定键、显示名称、扩展名、分类、大小、时间、下载状态、图标类型和可选缩略图地址。布局仅改变 CSS 网格和字段可见性：

- 平铺：自适应多列信息卡片。
- 详细信息：单列、多字段信息行。
- 列表：按纵向优先排列的紧凑多列列表。
- 小图标：高密度图标网格。
- 大图标：低密度大缩略图网格。

图片缩略图沿用现有按需缓存接口并使用懒加载；其他类型只使用静态类型图标。每个分类最近使用的查看方式保存到浏览器本地存储，键中包含功能版本但不包含端点，避免加入可同步的应用设置。

替代方案是为每种视图维护独立 DOM 和状态；该方案容易造成选择与分页状态分叉，因此不采用。

### Decision: 选择状态使用稳定键集合而不是 DOM 状态

选择模型维护 `Set<resourceKey>` 和 `Map<resourceKey, size>`。所有视图通过该模型派生复选框、选中样式、总数和总大小；分页、筛选或视图销毁不会改变选择。资料键至少组合端点、消息文件名和资源变体，以区分普通附件与语音消息的源音频。关闭未提交弹窗或成功提交批次后清空集合。

这种方式同时支持显式点击、当前页全选、全部筛选结果全选、刷选和框选，并避免依赖屏幕位置或当前 DOM 元素。

### Decision: 长按刷选采用 Pointer Events 状态机

指针在资料项上按下后启动约 300ms 的长按计时器，并允许少量移动容差。阈值到达后读取起始项当前状态，确定本次手势是“选择”还是“取消”，捕获指针并记录本次已经访问的资料键。移动期间使用 `elementFromPoint` 找到指针下的资料项，同一键只处理一次；靠近滚动容器上下边缘时通过动画帧驱动自动滚动。`pointerup`、`pointercancel`、窗口失焦或弹窗关闭均清理状态。

长按成立前保留正常滚动和点击；成立后禁止文本选择及图片原生拖拽。复选框和内部操作按钮不启动长按计时器。

替代方案是使用原生 HTML Drag and Drop；它更适合搬运对象，不适合连续经过项目时更新选择，而且图片原生拖拽会与选择冲突。

### Decision: 网格框选基于视口矩形相交计算

仅平铺、小图标和大图标视图允许从内容区空白位置启动框选。指针捕获后绘制绝对定位的选择矩形，通过当前已渲染资料项的 `getBoundingClientRect()` 判断相交，实时维护预选集合；释放时把预选集合并入正式选择。分页意味着框选只作用于当前页的可见/已渲染项，且不会清除旧选择。

列表与详细信息视图不提供框选，因为密集行布局更适合刷选，空白拖动也更容易与滚动混淆。

### Decision: 前端维护有限并发队列并复用后端单文件核心

提交时先根据选择集合读取最新资料元数据并生成批次快照，然后将每个需要下载的资料创建为排队任务。前端队列控制器默认最多同时运行 3 项，逐项调用后端下载命令；单项失败只结束该项并继续调度后续任务。任务模型增加 `queued` 状态，随后沿用现有 `progress`、`complete` 和 `error` 状态及下载页渲染。

后端把现有命令中的实际下载步骤抽取为可复用核心，使普通附件和语音源音频可以通过统一的资料描述执行，同时保持单文件命令兼容。待执行队列只在当前应用会话中存在；已经产生部分文件的任务继续由现有 `partial_downloads` 支持恢复。

替代方案是一次性后端批量命令。它会重复一套任务状态和事件聚合协议，并使现有单项任务 UI 难以复用，因此第一版不采用。

### Decision: 批量提交使用无打断的统一冲突策略

提交前根据下载历史、记录路径是否存在和部分下载记录，把选择分为跳过、续传/重新下载和普通下载，并向用户展示预计数量。执行时：

- 完整下载且文件仍存在：跳过。
- 下载记录存在但文件丢失：重新下载。
- 存在兼容部分文件：沿用断点续传。
- 目标目录存在不属于当前资料的同名文件：自动追加序号。

批量流程不显示逐文件冲突弹窗；单文件下载仍保留原有交互。

## Risks / Trade-offs

- [大量图片同时请求缩略图造成卡顿] → 只为进入视口的图片懒加载缩略图，并限制并行缩略图请求。
- [长按与滚动、点击发生冲突] → 使用长按阈值、移动容差、内部控件排除和明确的手势清理状态；在自动化测试中覆盖轻触、快速滚动和长按。
- [框选计算随项目数量增加变慢] → 框选仅计算当前页已渲染元素，使用动画帧合并移动事件。
- [跨筛选选择让用户忘记隐藏选择项] → 固定底部持续显示全部已选数量与大小，并提供清空全部选择。
- [轻量全选返回大量稳定键] → 只返回键和大小，不返回完整资料内容；若实际规模证明过大，再引入服务端选择令牌。
- [三个并发下载对较慢 WebDAV 端点压力过高] → 并发常量集中配置，单项仍使用已有超时与断点机制，后续可按实际反馈开放设置。
- [关闭应用会丢失尚未开始的排队项] → 第一版明确队列为会话级；已经开始的项目保留部分下载记录，未开始项目可重新选择。

## Migration Plan

1. 增加只读资料查询及选择解析接口，不改变现有数据库和 WebDAV 格式。
2. 增加弹窗和选择模型，在功能入口接通前完成组件级测试。
3. 将首页按钮替换为“下载”并接通弹窗；下载页保留原有入口和历史行为。
4. 增加排队状态和有限并发调度，验证单文件下载入口不受影响。
5. 若需要回滚，可隐藏新入口并移除前端弹窗；新增查询接口和本地查看偏好不会影响既有数据。
