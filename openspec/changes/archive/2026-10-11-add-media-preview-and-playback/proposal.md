# Proposal

## Why

当前图片只有部分入口能够显示缩略图，普通音频和视频在消息列表、预览弹框及批量下载弹框中仍只能作为文件处理，用户需要先完成正式下载并使用外部程序打开，无法快速确认媒体内容。需要建立统一的媒体预览资源和播放缓存能力，让图片、音频、视频在上传后即可被直观识别和按需预览。

## What Changes

- 统一图片和视频的预览图生成流程：上传媒体文件后异步生成轻量 JPEG 预览图、上传至 WebDAV 预览资源目录并保留端点隔离的本地缓存；预览图失败不影响原文件发送成功。
- 修复内存数据、粘贴及本机 HTTP 等临时文件上传入口可能在预览图任务读取前清理源文件的问题，使所有上传入口使用稳定数据源生成预览资源。
- 在选择待上传文件时为图片显示本地预览，为音频显示播放控制，为视频显示本地首帧或类型占位并提供播放入口。
- 在消息列表和消息全屏预览中展示图片缩略图、视频封面，并为普通音频、语音转写源音频和视频提供应用内播放。
- 扩展批量下载弹框，使图片和视频显示预览图，音视频在缩略图悬停或聚焦时显示播放入口；音频点击后在不改变卡片尺寸的前提下原位切换为带播放/暂停、可拖动进度条和时间信息的播放器，视频可从封面打开播放器，同时保证媒体控件不触发卡片选择或矩形框选。
- 新增独立于正式下载目录和下载历史的媒体预览缓存；播放时优先使用已有本地文件，其次使用预览缓存，否则按需缓存远端原文件后播放。
- 对 WebView 不支持的媒体格式显示明确提示，并保留下载及系统程序打开入口；第一版不包含自动转码和边下边播。

## Capabilities

### New Capabilities

- `media-preview-playback`: 图片/视频预览资源生成与缓存、音视频按需播放、格式回退及播放器生命周期。

### Modified Capabilities

- `message-feed`: 消息列表、上传选择区及消息全屏预览增加图片/视频预览和普通音视频播放行为。
- `bulk-download-dialog`: 批量下载资料视图增加视频预览图及音视频播放，并隔离播放控件与批量选择手势。

## Impact

- 后端上传链路：`send_file`、`send_file_data`、本机 HTTP 上传及其他复用发送核心的入口共享媒体预览生成逻辑。
- WebDAV 数据：增加版本化预览资源目录，同时继续兼容现有图片 `.thumbs` 缩略图，不修改原始媒体文件和消息 history 的基本格式。
- 本地缓存：增加端点隔离的预览图和媒体播放缓存，以及缓存清理和远端删除联动。
- 前端：上传附件区、消息列表、消息预览弹框和批量下载弹框接入统一媒体类型判断、预览加载、播放状态及错误回退。
- 依赖与打包：需要确定并集成可跨平台提取视频帧的媒体工具；优先采用随应用发布的受控 FFmpeg sidecar。
- 测试：覆盖各上传入口的预览生成、图片与视频预览回退、音视频播放缓存、格式不支持、播放器互斥和批量选择手势隔离。
