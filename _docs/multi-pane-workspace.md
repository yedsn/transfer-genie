# 多分栏工作区方案

本文档整理一个接近 VSCode 的多分栏工作区方案，目标是让 Transfer Genie 在写方案、梳理想法、对比内容和临时拆分任务时，具备更高密度的多文档编辑能力。

## 1. 方案目标

这个方案要解决的是“同时处理多个内容上下文”这类问题，而不是单纯把编辑器做得更复杂。

主要目标如下：

- 允许用户同时打开多个文档标签页。
- 允许用户把标签页拖入不同分栏。
- 允许用户快速创建左右分栏或上下分栏。
- 允许每个分栏保持自己的一组标签页。
- 允许消息列表中的消息像文档一样被拖入分栏。
- 允许文档或消息拖出主窗口，形成独立窗口。

## 2. 核心概念

### 2.1 工作区

工作区是最上层的容器，用来保存当前这次编辑会话的全部状态。

工作区保存的内容建议包括：

- 当前打开了哪些标签页。
- 每个标签页属于哪个分栏。
- 当前采用的分栏布局。
- 每个分栏的显示模式。
- 是否存在独立窗口。

### 2.2 分栏

分栏是屏幕上的可见编辑区域。一个分栏可以显示一个主文档，也可以同时承载多个标签页。

分栏建议支持以下状态：

- 单栏。
- 左右分栏。
- 上下分栏。
- 三列分栏。

### 2.3 标签页

标签页是文档、消息、图表或其他内容的打开实例。

一个标签页需要包含：

- 标题。
- 来源类型。
- 内容引用。
- 未保存状态。
- 所属分栏。

## 3. 布局模型

### 3.1 单栏

单栏用于专注编辑。它是默认入口，也适合移动内容时的中间态。

### 3.2 左右分栏

点击右上角的左右分栏按钮后，界面切成两栏：左侧一个分栏，右侧一个分栏。

再次点击同类按钮时，布局可以进一步扩展为三列分栏，形成更适合对比和参考的布局。

推荐行为：

- 第一次点击：创建左右双栏。
- 第二次点击：在当前布局基础上扩展为三列。
- 再次点击：根据当前状态循环切换或重置布局。

### 3.3 上下分栏

点击右上角的上下分栏按钮后，界面切成上下两栏。

这个布局更适合“上面看资料，下面写内容”或者“上面放正文，下面放图表”的场景。

### 3.4 三列分栏

三列分栏适合同时处理三种内容，例如：

- 左侧放原始需求。
- 中间放方案正文。
- 右侧放图表或预览。

## 4. 分栏内标签页

每个分栏都应支持多标签页。

这样做的目的不是让用户无限堆内容，而是让每个分栏成为一个小型工作台。

建议的交互：

- 同一分栏内可以切换多个标签页。
- 标签页可以固定。
- 标签页可以关闭，但关闭不等于删除内容。
- 标签页可恢复上次会话状态。

## 5. 拖拽停靠规则

拖拽停靠是这个方案的关键。

### 5.1 标签页拖到文档区域

当用户把标签页拖到某个文档区域时，系统根据落点决定停靠方式：

- 拖到右半部分：创建或切换为左右分栏。
- 拖到下半部分：创建或切换为上下分栏。
- 拖到中间区域：放入当前分栏的标签页集合。

### 5.2 标签页拖到已有分栏

如果目标区域已经是一个分栏，拖入后只需要把标签页加入该分栏，不一定要改整体布局。

### 5.3 消息拖到分栏

消息列表中的消息也应支持拖拽停靠，逻辑和标签页一致：

- 拖到右半部分：右侧分栏。
- 拖到下半部分：下方分栏。
- 拖到空白区域：新建分栏并打开该消息。

### 5.4 拖出主窗口

标签页或消息拖出主窗口时，系统应创建一个独立窗口承载该内容。

这个能力适合以下场景：

- 一边主窗口看消息流，一边单独放一份方案稿。
- 把某条消息固定在第二屏上做参考。
- 把图表拖到外部窗口，获得更大的编辑区域。

## 6. 独立窗口

独立窗口不是单独的产品功能，而是分栏能力的延伸。

建议支持的行为：

- 独立窗口可承载一个或多个标签页。
- 独立窗口可继续接收拖拽内容。
- 独立窗口关闭后，内容回到主工作区，不丢失。
- 独立窗口状态可恢复。

## 7. 推荐的界面入口

右上角建议放两个明确的分栏按钮：

- 左右分栏按钮。
- 上下分栏按钮。

按钮旁边可以继续保留常用操作，例如：

- 新建标签页。
- 关闭当前标签页。
- 在新窗口打开。

这样用户不需要先进入菜单再找布局选项。

## 8. 建议的交互流程

### 场景一：先写方案，再看资料

1. 打开主方案文档。
2. 点击左右分栏按钮。
3. 把参考消息拖到右侧。
4. 左侧继续编辑，右侧保持参考内容。

### 场景二：对比两个草稿

1. 打开两个草稿标签页。
2. 点击左右分栏按钮。
3. 把两个标签页分别拖到左右两侧。
4. 直接比较内容差异。

### 场景三：正文和图表并排

1. 打开方案正文。
2. 打开 Mermaid 图或图表标签页。
3. 将图表拖到右半部分。
4. 正文和图表同时保持可见。

### 场景四：把消息单独弹出

1. 从消息列表拖出某条消息。
2. 在主窗口外形成独立窗口。
3. 继续在主窗口处理其他内容。

## 9. 状态保存建议

为了让这个体验稳定，建议保存以下状态：

| 项目 | 说明 |
| --- | --- |
| 打开的标签页 | 下次启动时恢复 |
| 分栏结构 | 单栏、左右、上下、三列 |
| 分栏里的标签页顺序 | 维持用户的整理结果 |
| 当前激活标签页 | 恢复上次焦点 |
| 独立窗口列表 | 恢复到原来位置和内容 |

## 10. 范围建议

第一阶段建议只做最小闭环：

- 多标签页。
- 左右和上下分栏。
- 拖拽停靠。
- 独立窗口。

第二阶段再补：

- 三列分栏的更细控制。
- 分栏标题栏按钮。
- 标签页固定与恢复。
- 更复杂的内容预览模式。

## 11. 不建议一开始做的事

以下能力可以后置：

- 任意拖拽缩放分栏。
- 无限数量的嵌套分栏。
- 复杂的文档 diff/merge。
- 白板式自由画布。

这些功能都可能有用，但会明显增加状态管理和交互复杂度。

## 12. 结论

这套方案的重点不是“编辑器变成 IDE”，而是让 Transfer Genie 在处理多份材料时更像一个可组织的工作台。

如果只保留一句话，可以概括为：

> 用标签页管理内容，用分栏组织视野，用拖拽决定布局，用独立窗口扩展空间。
